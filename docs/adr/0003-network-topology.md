# ADR 0003: Network topology — no NAT gateway, RDS publicly reachable with forced TLS

**Status:** accepted (build); costed alternatives recorded
**Date:** 2026-09-19

## Context

Three of the four Lambdas need the public internet (GitHub API, the model API) and three need Postgres. The conventional shape — RDS in private subnets, Lambdas inside the VPC — makes internet egress from those Lambdas impossible without a NAT gateway.

NAT gateway in us-east-1: $0.045/hour ≈ **$32.85/month** before data processing ($0.045/GB). The rest of this stack at steady state is roughly: RDS `db.t4g.micro` ≈ $12–13/month, everything else inside free tiers or cents. The NAT gateway alone would exceed the entire remainder of the bill, on a project whose budget alarm is set at $10.

## Options

| | Monthly cost delta | Exposure | Notes |
|---|---|---|---|
| **1. Private RDS + NAT gateway** | +$33 + $0.045/GB | None beyond the VPC | The production-shaped answer. Interface endpoints for Secrets Manager / SQS / DynamoDB would add ~$7 each if used instead of NAT for those. |
| **2. Split placement** | +$0 (S3 gateway endpoint is free) | RDS private | `discover`/`fetch` outside the VPC (internet free); only Postgres-touching code inside. But `fetch` needs both GitHub *and* Postgres, and `api` needs both the model API *and* Postgres — so the split forces either a NAT anyway or moving the DB writes to a queue-and-writer hop. More moving parts to avoid a line item. |
| **3. Public RDS, TLS forced, SG-restricted, Secrets Manager** | +$0 | RDS endpoint reachable from the internet on 5432 | Chosen for the build. |

## Decision

Option 3. `infra/rds.tf`:

- `publicly_accessible = true`, single-AZ `db.t4g.micro`, gp3 20 GB, no backups (reproducible from S3).
- Parameter group `rds.force_ssl = 1`: plaintext connections are refused at the protocol level.
- Password is 32 random characters generated by Terraform, stored in Secrets Manager, read by Lambdas at cold start. The connection URL carries `sslmode=require`.
- Security group: 5432 from `admin_cidr` (the workstation /32) **and** from `0.0.0.0/0`. The second rule is the exposure, and it exists because non-VPC Lambdas egress from AWS's public address ranges, which are too numerous to enumerate.
- The database holds public CI history. There is nothing in it that isn't already on github.com.

## What this costs in security terms, stated plainly

The endpoint answers on the public internet. Anyone can attempt a TLS handshake and a password guess. Mitigations are the forced TLS, the 32-character secret, and the absence of sensitive data. Not mitigated: connection-exhaustion or brute-force noise against the instance, which on a `t4g.micro` could degrade the real workload. That risk is accepted for a portfolio system with a $10 budget and would not be accepted with a production one.

## With a production budget

Option 1, plus RDS Proxy (measured in a bounded window in Phase 6 rather than run continuously — it is ~$20/month for this instance class), plus Function URL auth switched from `NONE` to `AWS_IAM`.
